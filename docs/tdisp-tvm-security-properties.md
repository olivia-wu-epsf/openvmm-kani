# TDISP TVM Security Properties — Paravisor Obligations

This document records the falsifiable, spec-grounded security
properties the OpenHCL paravisor (acting as the **TVM** in PCI-SIG
TDISP v2022-07-27 terms) must enforce to protect its own
**confidentiality** and **integrity**, and the integrity of its
communication with a TEE Device Interface (TDI), against a fully
untrusted host VMM. **Availability is explicitly a non-goal** — the
TVM is allowed to refuse / `Err` any operation.

The list was derived **top-down from the spec only** (no
implementation reading) by a TDISP subject-matter expert subagent
(Claude Opus 4.7) loaded with the
[`.github/skills/tdisp-spec/SKILL.md`](../.github/skills/tdisp-spec/SKILL.md)
skill. SPDM crypto, IDE keying, and PSP/TSM measurement comparison
are **axiomatised** — the properties below are the residual local
pre/post-conditions the TVM-side TDISP handler must enforce on every
request it sends and every response it ingests.

Property categories:

- **(a)** state-machine ordering preconditions on outgoing requests
- **(b)** post-conditions / sanity checks on host-supplied responses
- **(c)** TDI-id binding
- **(d)** IDE/SPDM session binding
- **(e)** report verification
- **(f)** lock-nonce/epoch handling
- **(g)** MMIO/DMA gating before unblocking
- **(h)** teardown/scrubbing on Unbind/STOP

---

## TVM-1 — Outgoing-request state guard (UNLOCKED ⇒ LOCK)

**Property.** A `LOCK_INTERFACE_REQUEST` may be transmitted for a TDI
iff the TVM's locally tracked TDI state is `CONFIG_UNLOCKED`.
**Cite.** §11.3.1 Table 3 ("Legal TDISP states for Device:
CONFIG_UNLOCKED"); state machine §11.2.
**Category.** (a).

## TVM-2 — Outgoing-request state guard (LOCKED|RUN ⇒ GET_REPORT)

**Property.** `GET_DEVICE_INTERFACE_REPORT` may be issued only when
locally tracked state is `CONFIG_LOCKED` or `RUN`.
**Cite.** §11.3.1 Table 3; §11.3.10.
**Category.** (a).

## TVM-3 — Outgoing-request state guard (LOCKED ⇒ START)

**Property.** `START_INTERFACE_REQUEST` may be issued only when
locally tracked state is `CONFIG_LOCKED` *and* a valid cached nonce
exists from the LOCK that produced this epoch.
**Cite.** §11.3.1 Table 3; §11.3.14.
**Category.** (a) + (f).

## TVM-4 — Outgoing-request state guard (RUN-only operations)

**Property.** `BIND_P2P_STREAM_REQUEST`, `UNBIND_P2P_STREAM_REQUEST`,
and `SET_MMIO_ATTRIBUTE_REQUEST` may be issued only when locally
tracked state is `RUN`.
**Cite.** §11.3.1 Table 3 (legal state column = RUN).
**Category.** (a).

## TVM-5 — Response opcode discipline

**Property.** For every outstanding request of code *X*, the only
acceptable response codes are *response(X)* and `TDISP_ERROR`. Any
other code (including unknown/reserved) must be treated as
`TDISP_ERROR` and must not advance local state.
**Cite.** §11.3.2 Table 4: *"Undefined/unsupported response codes must
be treated as if they were TDISP_ERROR."*
**Category.** (b).

## TVM-6 — Response/request INTERFACE_ID binding

**Property.** Every response is accepted only if its common-header
`INTERFACE_ID` (Function/Segment/Bus/Device, Table 1) equals the
`INTERFACE_ID` of the in-flight request the TVM has bound it to.
Otherwise drop and treat as a host attack.
**Cite.** §11.3.3 Table 5 common header; §11.1 Figure 11-4 + Table 1;
§11.5.4 device binding.
**Category.** (c) + (b).

## TVM-7 — TDISP version pinning

**Property.** After `GET_TDISP_VERSION` / `TDISP_VERSION` negotiation,
the TVM must reject any subsequent TDISP message whose version field
does not equal the negotiated version. No mid-stream version
downgrade.
**Cite.** §11.3.3; §11.3.4–11.3.5.
**Category.** (b).

## TVM-8 — Lock-nonce capture & single-use

**Property.** On a valid `LOCK_INTERFACE_RESPONSE`, the TVM caches
the 32-byte `START_INTERFACE_NONCE` exactly once per (TDI,
lock-epoch). The very next `START_INTERFACE_REQUEST` for that TDI must
carry that exact 32-byte value; the cached nonce must then be marked
consumed and never reused for any subsequent request.
**Cite.** §11.3.9 Table 11; §11.3.14: *"START_INTERFACE_NONCE in the
request is not valid i.e., does not match the nonce generated by the
device in the LOCK_INTERFACE_RESPONSE."*
**Category.** (f).

## TVM-9 — Nonce destruction on epoch exit

**Property.** Whenever the TVM observes (or causes) any transition of
the TDI out of `CONFIG_LOCKED` (to `CONFIG_UNLOCKED`, `ERROR`, or
`RUN`), the cached `START_INTERFACE_NONCE` is destroyed immediately
and any subsequent `START_INTERFACE_REQUEST` requires a fresh
`LOCK_INTERFACE_REQUEST` round.
**Cite.** §11.3.9: *"This nonce must be destroyed when the TDI moves
to CONFIG_UNLOCKED or ERROR from CONFIG_LOCKED"*; §11.3.14 (must be
invalidated before RUN).
**Category.** (f) + (h).

## TVM-10 — Same-SPDM-session epoch for the LOCK→REPORT→START chain

**Property.** All three of `LOCK_INTERFACE_REQUEST`, the
`GET_DEVICE_INTERFACE_REPORT` exchanges that justify acceptance, and
`START_INTERFACE_REQUEST` for a given TDI must be carried over the
*same* SPDM secure session. If the underlying SPDM session terminates
or rotates between LOCK and START, the TVM must abandon the chain and
force ERROR / re-LOCK.
**Cite.** §11.6.3: *"all transitions through the TDISP state machine
occur due to TDISP requests generated in the same SPDM secure
session"*; §11.6.1 on session-termination ⇒ TDI ERROR.
**Category.** (d) + (f).

## TVM-11 — Device identity match (Question 2 of §11.2.7)

**Property.** Before transitioning local state to RUN-accepted, the
TVM must obtain from the TSM (axiomatised) the SPDM-authenticated
device identity of the DSM and verify it equals the identity the TVM
has tied to this TDI's measurements. Mismatch ⇒ refuse to accept TDI.
**Cite.** §11.2.7 Q2.
**Category.** (d) + (e).

## TVM-12 — IDE-keying provenance (Question 3 of §11.2.7)

**Property.** When IDE is required for the TDI, the TVM must verify
(via TSM-provided interface) that all IDE keys for the TDI's stream
were established/verified by the TSM over the *same* SPDM session as
the LOCK. Otherwise refuse acceptance.
**Cite.** §11.2.7 Q3; §11.3.8 IDE precondition list; §11.6.1 /
§11.6.3.
**Category.** (d).

## TVM-13 — Report fragment reassembly invariants

**Property.** Across a series of `GET_DEVICE_INTERFACE_REPORT`
round-trips: (i) request `OFFSET₀ = 0`; (ii) for *k>0*,
`OFFSETₖ = Σⱼ<ₖ PORTION_LENGTHⱼ`; (iii) `PORTION_LENGTHₖ ≤ LENGTHₖ`;
(iv) reassembly terminates iff `REMAINDER_LENGTH = 0`; (v) total
assembled length equals the sum of `PORTION_LENGTH`s. Any deviation
⇒ reject the report.
**Cite.** §11.3.10 Table 13; §11.3.11 Table 14; Figure 11-7.
**Category.** (b) + (e).

## TVM-14 — Report internal consistency

**Property.** Parsed `DEVICE_INTERFACE_REPORT` must satisfy: MMIO
ranges are non-overlapping; MSI-X-Table / MSI-X-PBA range-attribute
bits are set only if the corresponding `LOCK_MSIX` bit was requested
in the matching `LOCK_INTERFACE_REQUEST`; bit fields in INTERFACE_INFO
and range-attribute reserved bits are zero; `IS_MEM_ATTR_UPDATABLE`
semantics honoured only on later `SET_MMIO_ATTRIBUTE_REQUEST`.
**Cite.** §11.3.11 Table 15; §11.3.8 LOCK_MSIX semantics.
**Category.** (e).

## TVM-15 — Mapping check (Question 4 of §11.2.7)

**Property.** Before unblocking guest access, the TVM must verify
that the VMM's mapping of TDI MMIO into the TVM's address space
matches the report exactly: same set of physical ranges (after
subtracting `MMIO_REPORTING_OFFSET`), same logical / BAR order as
reported, and no unexpected overlap with other TDIs/ranges already
accepted into the TCB.
**Cite.** §11.2.7 Q4; §11.3.8 `MMIO_REPORTING_OFFSET`; §11.3.11
ordering rule "MMIO ranges must be reported in the logical order…";
§11.6.3 on overlap/redirect attacks.
**Category.** (e) + (g).

## TVM-16 — DMA/MMIO unblock gate

**Property.** The TVM must not enable guest-visible DMA acceptance
from, or T-bit MMIO traffic to, the TDI until *all* of:
(i) local state == `RUN`,
(ii) a `START_INTERFACE_RESPONSE` for the matching
`(INTERFACE_ID, nonce)` has been validated,
(iii) §11.2.7 Q1–Q4 have all been answered yes.
**Cite.** §11.2.7; §11.6.3; §11.5.2 / §11.5.3.
**Category.** (g).

## TVM-17 — Non-TEE memory must not be admitted as confidential

**Property.** MMIO ranges in the report with `IS_NON_TEE_MEM = 1` must
never be mapped into the TVM as TEE/confidential memory and must not
receive T-bit-set TLPs from TVM code. Updates via
`SET_MMIO_ATTRIBUTE_REQUEST` are only honoured if the original range
had `IS_MEM_ATTR_UPDATABLE = 1`.
**Cite.** §11.3.11 Table 15 bits 2–3; §11.3.22; §11.6.3 last
paragraph.
**Category.** (e) + (g).

## TVM-18 — Local state on observed/induced ERROR

**Property.** If a TDISP_ERROR is received for any in-flight request,
or `GET_DEVICE_INTERFACE_STATE` returns `ERROR`, or any of the
response-validation checks above fails, the TVM must transition its
local TDI state to `ERROR`, gate off DMA/MMIO immediately, destroy
the cached nonce and report, and require a fresh LOCK round before
reuse.
**Cite.** §11.3.13 Table 17; §11.3.24; §11.6.3.
**Category.** (h) + (b).

## TVM-19 — Teardown scrubbing on STOP/UNBIND

**Property.** On `STOP_INTERFACE_RESPONSE` (or any host-driven exit
from RUN that the TVM accepts), the TVM-side state for that TDI —
cached nonce, cached report, cached MMIO mapping decisions, derived
per-TDI keys/contexts, p2p bind state — must be scrubbed before any
new LOCK is permitted. UNBIND_P2P symmetric for the P2P stream's
local state.
**Cite.** §11.3.16 device-side scrub list; §11.3.9 nonce destruction;
§11.3.20 UNBIND_P2P.
**Category.** (h).

## TVM-20 — One-in-flight per TDI (request/response pairing)

**Property.** The TVM must serialize TDISP requests per TDI: only one
outstanding TDISP request per `INTERFACE_ID` at a time, and a response
is matched to that single in-flight request. This denies the host the
ability to satisfy request *A* with the response to a different
earlier or concurrent request *B* on the same session.
**Cite.** §11.3.3 common header / request-response pairing; §11.6.1
reorder/replay threat; §11.6.3.
**Category.** (b) + (c).

## Underdetermined-by-spec note

The spec is silent on *how* the TVM should serialize requests
(TVM-20) and on the exact algorithm for verifying VMM-supplied
mappings against the report (TVM-15) beyond §11.2.7 Q4 and the
§11.6.3 ordering requirement; both are necessary consequences but the
spec leaves the mechanism to the implementation.
